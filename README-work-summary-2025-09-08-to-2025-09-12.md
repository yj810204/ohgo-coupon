### 2. 승선 명부 페이지 로딩 최적화 (2025년 9월 12일)
승선 명부 페이지의 로딩 성능을 크게 향상시켰습니다. 주요 개선 사항은 다음과 같습니다:

#### 문제점
승선 명부 페이지(`today-roster.tsx`)에 처음 들어올 때 로딩 시간이 너무 오래 걸리는 문제가 있었습니다.

#### 구현된 최적화
1. **배치 쿼리 사용**: 개별 날짜별 쿼리 대신 월 단위로 배치 쿼리를 사용하여 31개의 개별 쿼리 대신 단 2개의 쿼리만 실행하도록 변경했습니다.
2. **데이터 캐싱 구현**: 이전에 로드한 월 데이터를 캐싱하여 사용자가 이미 방문한 월로 돌아갈 때 즉시 데이터를 표시할 수 있도록 했습니다.
3. **캐시 크기 제한**: 메모리 사용량을 제한하기 위해 최대 3개월의 데이터만 캐시에 유지하도록 구현했습니다.
4. **로딩 상태 타임아웃**: 로딩 상태가 무한정 지속되는 것을 방지하기 위해 10초 타임아웃을 추가했습니다.
5. **캐시 사용 시각적 표시**: 사용자에게 캐시된 데이터가 사용되고 있음을 알리기 위한 시각적 표시를 추가했습니다.

#### 개선 효과
- 로딩 시간 단축
- 반응성 향상
- 네트워크 사용량 감소
- 사용자 피드백 개선

### 3. UUID 일관성 문제 해결 (2025년 9월 12일)
관리자가 등록한 사용자와 앱을 통해 직접 가입한 사용자 간의 UUID 불일치 문제를 해결했습니다.

#### 문제점
관리자가 새로운 비회원을 등록하면 시스템에 새 회원이 됩니다. 그러나 해당 사용자가 실제 앱을 다운로드하고 등록된 정보로 로그인하면 새로운 UUID가 발급되어 시스템에서 다른 사람으로 인식되는 문제가 있었습니다.

#### 원인
- `firebase-auth.ts`에서는 사용자 이름과 생년월일을 기반으로 `uuidv5`를 사용하여 결정론적 UUID를 생성했습니다.
- `roster-member-search.tsx`에서는 관리자가 새 사용자를 등록할 때 무작위 UUID를 생성했습니다.

#### 해결 방법
- `roster-member-search.tsx`를 수정하여 `firebase-auth.ts`와 동일한 결정론적 UUID 생성 방법을 사용하도록 했습니다.
- 일관된 생년월일 형식을 보장하기 위해 동일한 `normalizeDob` 함수를 추가했습니다.

#### 이점
- 관리자가 등록한 사용자가 앱을 통해 로그인해도 동일한 사용자로 인식됩니다.
- 중복 사용자 레코드가 생성되지 않습니다.
- 시스템 전체에서 사용자 데이터 일관성이 유지됩니다.

### 4. 미끼 개수 표시 버그 수정 (2025년 9월 9일)
게임 초기 로딩 시 미끼 개수가 잠깐 잘못 표시되는 버그를 수정했습니다.

#### 문제점
게임 초기 로딩 시 남은 미끼가 잠깐 20개 보였다가 실제 남은 수가 보이는 현상이 발생했습니다.

#### 원인
- 미끼 개수(`baitCount`)가 초기에 0으로 설정되었지만, Firebase에서 데이터를 가져오는 과정에서 `dailyBaitLimit`이 먼저 업데이트되고 `todayBaitUsed`가 나중에 업데이트되는 경우가 있었습니다.
- `useEffect` 훅이 `dailyBaitLimit`과 `todayBaitUsed` 값이 변경될 때마다 `baitCount`를 업데이트했기 때문에, 실제 값이 모두 로드되기 전에 중간 상태가 UI에 표시되었습니다.

#### 해결 방법
- 미끼 로딩 상태를 추적하는 `baitLoading` 상태 변수를 추가했습니다.
- 미끼 개수가 계산되는 `useEffect`를 개선하여 실제 데이터가 로드된 후에만 `baitCount`를 업데이트하도록 했습니다.
- UI를 업데이트하여 미끼 개수가 로딩 중일 때 "미끼 정보 로딩 중..." 메시지를 표시하도록 했습니다.
- 미끼 정보가 로딩 중일 때는 시작 버튼과 미끼 교환권 버튼을 비활성화했습니다.
